# Check before deploy

A gate, not a report. It ends in PASS or a numbered list of things to fix.

This dashboard holds a dealer's sales, gross and ad spend. An unlisted Vercel URL is not access
control, it is a URL that has not been found yet. Background and the reasoning are in `SECURITY.md`
and `AUTH.md`.

Run every check. Do not stop at the first failure, because the person running this wants one list,
not five rounds. Read files and grep; do not modify anything until the user says to fix.

## The checks

### 1. There is an auth gate at all

Find `middleware.ts` or `middleware.js` (on current Next.js the same gate may be named `proxy.ts` /
`proxy.js` instead; accept either). If none exists and Vercel password protection is not in use,
this is an automatic FAIL. Ask which of the three options in `AUTH.md` they want and offer to
write it.

### 2. The gate fails closed

Read the gate. If the password env var is missing at runtime, it must **deny**. The failure mode is:

```ts
if (!expected) return NextResponse.next();   // WRONG. Publishes everything.
```

That line, or anything equivalent, is a FAIL. It is the bug that silently opens the dashboard the
first time an env var does not propagate, and it looks completely fine in code review.

### 3. The matcher covers API routes

Read the `config.matcher`. A matcher that only covers pages leaves `/api/*` serving the full dataset
as JSON to anyone who asks. It must cover everything except static assets. Confirm by reading the
pattern, and say which paths it excludes.

### 4. Nothing secret is exposed to the browser

Grep the source and any `.env.example` for `NEXT_PUBLIC_`. Every hit is bundled into client
JavaScript and visible in DevTools by design. For each one, say what it holds. A title or a feature
flag is fine. A password, key, token, connection string or service role key is a FAIL.

Do not read `.env` files to do this. Check variable names in source, not values.

### 5. No secret is hardcoded

Grep the source for assignments to anything named like `password`, `secret`, `token`, `api_key`,
`apikey`, `service_role`, and for long base64-looking or `sk-` prefixed literals. Report the file
and line. Never print the value.

### 6. No data file is served or tracked

If the folder is not a git repository (the toolkit was downloaded as a zip), run
`git init && git add -A && git commit -m "toolkit"` first, then run these checks; a fresh repo
with only the kit's fixtures passes.

- The kit ships **known synthetic fixtures** that are allowed to be tracked and are NOT a failure:
  `sample-data/leads_monthly.csv` and everything under `demo-data/` (generated by the kit's own
  scripts, no real dealer, no PII). Treat these as an allowlist.
- `git ls-files '*.csv' '*.db' '*.sqlite' '*.db-wal' '*.db-shm' '*token*.json' 'data/*'` must return
  nothing **outside that allowlist**. The framework adds a database, token files and saved reports
  under `data/`; they are dealer data exactly like the CSV. Any other tracked `.csv` is
  the dealer's real data in the repo now: FAIL.
- `git log --all --diff-filter=A --name-only -- '*.csv'` must show no `.csv` **outside the
  allowlist** ever added. A file deleted later is still in history and still readable. If a real one
  is there, say plainly that removing it needs a history rewrite and a new repo is usually faster.
  Never rewrite history yourself.
- Nothing data-shaped in `public/`. Anything in `public/` is served to the world with no auth,
  including by the middleware above, because static assets are exactly what the matcher excludes.

### 7. `.gitignore` actually covers it

Confirm `*.csv` and `.env*` are present. Confirm `git status` is clean of untracked data files.

### 8. The manual check they have to do themselves

You cannot verify this one from here, so end by telling them to do it:

> Open the live URL in a private window with no session. You should get a password prompt before you
> see a single number. Then load one `/api/` route in that same window. You should get a 401, not
> JSON.

## Output

```
CHECK BEFORE DEPLOY

  1. Auth gate present            PASS   middleware.ts
  2. Fails closed                 PASS
  3. Matcher covers /api          FAIL   excludes /api/*, see below
  4. No secrets in NEXT_PUBLIC_   PASS   1 var, NEXT_PUBLIC_STORE_NAME
  5. No hardcoded secrets         PASS
  6. No data in git or public/    PASS   only kit fixtures tracked (sample-data, demo-data)
  7. .gitignore covers data       PASS

  1 to fix before this gets a URL:
  [3] middleware.ts:4 matcher is ["/((?!api|_next).*)"]. Remove `api|`.

  Then, in a private window: password prompt before numbers, 401 on /api.
```

Offer to fix what you found. Do not deploy for them, and do not treat "it is just for a minute to
show someone" as a reason to skip a failure.
